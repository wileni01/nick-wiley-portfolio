Coding assistants shorten the time between asking for a change and getting a diff to review. I get the most out of that when I can still explain what changed and run a test that would fail if the change were wrong.

For a refactor, I like to capture the existing behavior in a test first, then change one part at a time. That makes it easier to find the source of a regression and hand the work to someone else. It also makes me more willing to throw away a proposed change if it creates extra work.

Teams will need different release processes depending on what their software does. Across those settings, smaller changes and quick feedback make it easier to see where an assistant helped and where it made the code harder to maintain.
