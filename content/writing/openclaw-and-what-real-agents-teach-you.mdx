When evaluating an agent, I start with one job I can describe clearly. What information does it need, what tools may it use, and what should happen if an input is missing or a tool fails?

A narrow job makes it easier to test with real examples. I’d keep a record of the agent’s actions and the tool responses, so I could reproduce a failure and see whether a change fixed it. Prompts and permissions should be versioned with the tests.

For a task with consequences outside the chat, I also want a point where a person can review the proposed action. The right place for that review depends on what the tool can do and how hard an error would be to undo.
